## 1. Структура проекта

```
Проект/
├── main.py                 # точка входа GUI-приложения
├── news_server.py          # точка входа сервера новостей
├── requirements.txt        # внешние зависимости
├── scripts/                # программные модули
│   ├── data_loader.py      #   загрузка БД и денормализация
│   ├── text_reports.py     #   текстовые отчёты
│   ├── graphic_reports.py  #   графические отчёты (диаграммы)
│   ├── auth.py             #   учётные записи, хеширование, KYC
│   ├── api_client.py       #   клиент внешнего API (CoinGecko)
│   └── news_store.py       #   локальная лента + клиент сервера новостей
├── database/               # все данные приложения
│   ├── crypto_database.xlsx#   основная база (6 листов, 3НФ)
│   ├── users_db.xlsx       #   создаётся: учётные записи
│   ├── news_db.xlsx        #   создаётся: локальная лента
│   ├── server_news.xlsx    #   создаётся сервером: общая лента
│   ├── config.pkl          #   создаётся: настройки (тема, адрес сервера)
│   ├── session.pkl         #   создаётся: активная сессия
│   └── avatars/            #   создаётся: загруженные аватары
└── docs/                   # руководства
```

**Принцип организации путей.** Точки входа (`main.py`, `news_server.py`) лежат
в корне. Модули вынесены в `scripts/`; `main.py` добавляет эту папку в
`sys.path` перед их импортом. Все данные пишутся в `database/` независимо от
того, какой модуль их создаёт: каждый модуль вычисляет корень проекта как
родительскую папку относительно своего расположения (а в собранном `.exe` —
папку рядом с исполняемым файлом).

## 2. Архитектура

Многоуровневая, со строгим разделением ответственности:

| Уровень | Файлы | Задача |
|---|---|---|
| Представление | `main.py` | GUI (Tkinter): авторизация, кабинет, вкладки, темы |
| Сервисы | `auth.py`, `api_client.py`, `news_store.py` | учётные записи, API, новости |
| Бизнес-логика | `text_reports.py`, `graphic_reports.py` | отчёты и диаграммы |
| Данные | `data_loader.py` | чтение Excel, денормализация (merge) |
| Сеть | `news_server.py` | HTTP-сервер новостей |

Уровень представления не выполняет вычислений — только вызывает функции
нижних уровней. Модули отчётов и данных не зависят от GUI и тестируются
автономно.

## 3. Зависимости и установка

Внешние библиотеки: `pandas`, `numpy`, `matplotlib`, `openpyxl`. Всё
остальное — стандартная библиотека Python (`tkinter`, `urllib`,
`http.server`, `hashlib`, `pickle`, `secrets`).

### Linux (Debian/Ubuntu)

```bash
sudo apt install python3-venv python3-tk
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Либо без venv, системными пакетами:

```bash
sudo apt install python3-pandas python3-numpy python3-matplotlib \
                 python3-openpyxl python3-tk
```

### Windows

Установить Python с python.org (отметить «Add to PATH»; tkinter входит в
комплект), затем:

```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
```

### Anaconda (Windows / Linux / macOS)

Anaconda поставляется с tkinter, поэтому отдельная установка графической
библиотеки не требуется.

```bash
# создание и активация изолированного окружения
conda create -n crypto python=3.12
conda activate crypto

# установка зависимостей (канал conda-forge)
conda install -c conda-forge pandas numpy matplotlib openpyxl

# запуск из корня проекта
python main.py
# сервер новостей
python news_server.py 8765
```

Альтернативно зависимости можно поставить через pip внутри conda-окружения:
`pip install -r requirements.txt`. Команды conda выполняются в **Anaconda
Prompt** (Windows) или в терминале после `conda init` (Linux/macOS).
Деактивация окружения — `conda deactivate`.

## 5. Сервер новостей

`news_server.py` — `ThreadingHTTPServer` на стандартной библиотеке.
Слушает `0.0.0.0:<порт>`, что разрешает подключения по сети. Маршруты:

| Метод | Путь | Действие |
|---|---|---|
| `GET`  | `/news` | вернуть всю ленту в формате JSON |
| `POST` | `/news` | добавить запись (тело — JSON одной новости) |

Общая лента хранится в `database/server_news.xlsx`. Клиент (`news_store.py`)
устраняет дубликаты по полям `ID + АВТОР + ДАТА`.

Адрес сервера задаётся на каждом клиенте через интерфейс
(«Новости» → «Указать сервер») и сохраняется в `database/config.pkl`
(`main.py` подставляет его в `news_store.SERVER_URL` при запуске).

## 6. Публикация сервера через ngrok

В локальной сети достаточно сообщить клиентам локальный IP сервера. Чтобы
сделать сервер доступным **из интернета без проброса портов на роутере**,
удобно использовать туннель **ngrok**. Он выдаёт публичный HTTPS-адрес,
переадресующий трафик на ваш локальный сервер.

### Шаг 1. Установка ngrok

- Зарегистрируйтесь на https://ngrok.com и получите **authtoken** в личном
  кабинете.
- Установите ngrok:
  - **Linux (Debian):** скачайте архив с ngrok.com и распакуйте, либо
    `sudo snap install ngrok`;
  - **Windows:** скачайте `ngrok.exe` с сайта и распакуйте в любую папку.
- Однократно сохраните токен:

  ```bash
  ngrok config add-authtoken <ВАШ_ТОКЕН>
  ```

### Шаг 2. Запуск сервера и туннеля

Откройте **два** терминала.

Терминал 1 — локальный сервер новостей:

```bash
python news_server.py 8765
```

Терминал 2 — туннель ngrok на тот же порт:

```bash
ngrok http 8765
```

ngrok покажет строку вида:

```
Forwarding   https://a1b2-c3d4.ngrok-free.app -> http://localhost:8765
```

Публичный адрес — это часть до стрелки, например
`https://a1b2-c3d4.ngrok-free.app`.

### Шаг 3. Подключение клиентов

На каждом клиенте: «Новости» → «Указать сервер» → вставить публичный адрес
ngrok (целиком, со `https://`, **без** завершающего `/`):

```
https://a1b2-c3d4.ngrok-free.app
```

После этого публикация и синхронизация новостей идут через туннель.

### Проверка

```bash
curl -H "ngrok-skip-browser-warning: true" https://a1b2-c3d4.ngrok-free.app/news
```

Должен вернуться JSON-список новостей.

### Важные замечания

- **Бесплатный ngrok меняет адрес** при каждом перезапуске туннеля — после
  перезапуска нужно заново сообщить клиентам новый адрес. Постоянный поддомен
  доступен на платных тарифах.
- **Страница-предупреждение ngrok.** На бесплатном тарифе ngrok по умолчанию
  отдаёт HTML-заглушку вместо ответа сервера. Клиент приложения обходит это
  автоматически — он добавляет к запросам заголовок
  `ngrok-skip-browser-warning: true` (см. `scripts/news_store.py`). Поэтому
  синхронизация через ngrok работает «из коробки»; этот же заголовок нужно
  указывать при ручной проверке через `curl`.
- Туннель работает, **пока запущены оба процесса** (сервер и `ngrok`). При
  закрытии терминала ngrok адрес перестаёт действовать.
- ngrok передаёт трафик по HTTPS — `urllib` в клиенте корректно с этим
  работает, дополнительных настроек не требуется.

## 7. Модель данных

`crypto_database.xlsx` — 6 листов в третьей нормальной форме: категории,
криптовалюты, биржи, торговые пары, торговые данные, API. `data_loader.py`
читает их и строит денормализованную таблицу через цепочку `merge`
(аналог SQL JOIN). Данные внешнего API записываются в отдельные листы
`API_КУРСЫ` и `API_ИСТОРИЯ`, не затрагивая исходную структуру.

---

## 8. Безопасность

- Пароли не хранятся в открытом виде: сохраняется `SHA-256(соль + пароль)`
  и индивидуальная соль (`secrets.token_hex(16)`).
- Поля `ЛОГИН`, `ХЕШ_ПАРОЛЯ`, `СОЛЬ`, `KYC` защищены от изменения из
  приложения (множество `protected` в `auth.update_profile`). Поле `KYC`
  меняется только администратором вручную в `database/users_db.xlsx`.

## 9. Внешний API (CoinGecko)

`api_client.py` обращается к CoinGecko средствами `urllib` (без `requests`).
Сопоставление «тикер → id монеты» задано в словаре `TICKER_TO_ID`. Реализован
трёхуровневый фолбэк: реальное время → кеш в Excel → локальная база. Каждая
функция возвращает источник данных (`"api"` / `"cache"` / `"none"`).

Для CoinMarketCap предусмотрен хук `CMC_API_KEY` (требует платного ключа,
по умолчанию выключен).

## 10. Сборка автономного `.exe` (PyInstaller, Windows)

> Собирать `.exe` под Windows нужно **на Windows** — PyInstaller не выполняет
> кросс-компиляцию.

```bat
python -m pip install pyinstaller
pyinstaller --onefile --windowed ^
  --name CryptoApp ^
  --paths scripts ^
  --hidden-import data_loader --hidden-import text_reports ^
  --hidden-import graphic_reports --hidden-import auth ^
  --hidden-import api_client --hidden-import news_store ^
  --add-data "database/crypto_database.xlsx;." ^
  main.py
```

Пояснения:

- `--paths scripts` и `--hidden-import` нужны, потому что модули
  импортируются из подпапки `scripts/` через `sys.path`, и PyInstaller не
  обнаруживает их автоматически.
- `--add-data "database/crypto_database.xlsx;."` упаковывает базу внутрь
  сборки. При первом запуске `main.py` копирует её в `database/` рядом с
  `.exe` (см. блок путей в `main.py`).
- В собранном виде все данные пишутся в папку `database/` рядом с `.exe`,
  поэтому аккаунты, новости и настройки сохраняются между запусками.
